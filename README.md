# 한국어 낚시성 기사 탐지

KPF-BERT에 내부 일치도 피처를 붙여 낚시성 기사를 분류한 캡스톤 프로젝트입니다.

- 동덕여대 데이터사이언스 캡스톤디자인, 2026년 1학기, 2인 팀 (심가연, 이수현)
- 한국멀티미디어학회 춘계학술발표대회 포스터 발표 (2026-05-08, 대전)

## 요약

제목을 바꿔치기한 낚시성 기사는 F1 0.98로 잘 잡혔습니다.
본문 중간에 엉뚱한 문장 하나를 끼워 넣은 유형은 F1 0.76에서 더 오르지 않았습니다.
여러 방법을 시도하다가 마지막에 진단용 테스트셋을 직접 만들어 보니, 모델이 끼워 넣은 문장을 알아보는 게 아니라 학습 데이터의 패턴에 기대고 있었습니다.

## 데이터

[AI Hub 낚시성 기사 탐지 데이터](https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=71338)

| | Part1 제목-본문 불일치 | Part2 본문 이질 문장 삽입 |
|---|---|---|
| 입력 | `fakeTitle [SEP] newsContent` | `newsTitle [SEP] newsContent` |
| 학습 | 87,000건 | 87,000건 |
| 검증 | 36,434건 | 36,910건 |

학습셋은 원본에서 라벨 기준 층화 샘플링(`random_state=42`)했고, 라벨 비율은 약 50:50입니다. 검증셋은 원본 검증셋 전체를 썼습니다.

## 방법

1. 사전학습 모델 세 개를 비교했습니다: KoBERT(`monologg/kobert`), KLUE-RoBERTa(`klue/roberta-base`), KPF-BERT(`jinmang2/kpfbert`).
2. 가장 강한 KPF-BERT에만 피처를 붙여 효과를 봤습니다 (ablation).
   - 제목-본문 코사인 유사도 (Sentence-BERT)
   - 주제 일관성 비율 `subjectConsistencyRatio` (Part2만)
   - 결합: [CLS] 768차원 + 피처 → Linear(256) → ReLU → Dropout → Linear(2)
3. 학습: 3 epoch, batch 16, lr 1e-5, AdamW, max length 512, Kaggle Tesla T4. 평가는 weighted F1.

## 결과

### 모델 비교 (최고 epoch, weighted F1)

| 모델 | Part1 | Part2 |
|---|---|---|
| KoBERT | 0.813 | 0.685 |
| KLUE-RoBERTa | 0.979 | 0.748 |
| **KPF-BERT** | **0.982** | **0.760** |

뉴스 기사로 사전학습한 KPF-BERT가 두 Part 모두 가장 높았습니다. Part1에서 KLUE-RoBERTa와의 차이는 0.2%p입니다.

### 피처 추가 (KPF-BERT)

| | 추가한 피처 | F1 | 차이 |
|---|---|---|---|
| Part1 | 없음 | 0.9815 | |
| Part1 | + 코사인 유사도 | 0.9817 | +0.02%p |
| Part2 | 없음 | 0.7601 | |
| Part2 | + 주제 일관성 | 0.7617 | +0.16%p |
| Part2 | + 주제 일관성 + 코사인 | 0.7516 | −0.85%p |

Part2에서 코사인 유사도는 낚시성 0.4911, 정상 0.4909로 차이가 없었고, 넣으면 오히려 떨어졌습니다.
다만 같은 설정으로 베이스라인을 다시 학습하니 0.7634가 나왔습니다(+0.33%p). 재학습 변동이 피처 효과보다 커서, 주제 일관성 피처가 도움이 됐다고 말하기는 어렵습니다.

## Part2 성능을 올리려던 시도

베이스라인(0.7601)을 의미 있게 넘긴 시도는 없었습니다.

| | 시도 | 결과 | 안 된 이유 |
|---|---|---|---|
| 1 | 문장별 유사도 표준편차 | F1 0.7554 | 끼워 넣은 문장 하나가 나머지 문장에 묻힘 |
| 2 | 인접 문장 유사도 급락 등 구조 피처 | F1 0.7589 | 낚시성 본문이 더 짧아서 급락 횟수 차이가 반대로 나옴 |
| 3 | 제목 키워드의 본문 등장 비율 | 0.7468 vs 0.7463 | 같은 뉴스 도메인이라 어휘 차이가 없음 |
| 4 | 기사 앞부분과 전체를 따로 인코딩 | F1 0.7510 | 44.9%가 512토큰을 넘는데, 나누면서 문맥이 끊김 |
| 5 | 주제 일관성으로 손실 가중치 | 향상 없음 | 가중할 신호 자체가 약함 |
| 6 | 문장 쌍이 자연스러운지 분류 | 쌍 단위 F1 0.843 → 기사 단위 약 0.34 | 뉴스는 원래 인접 문장끼리도 끊겨 있고, 학습과 추론의 분포가 다름 |
| 7 | 난이도 '하'(자동 삽입)만 학습 | 소폭 하락 | 자동 삽입 패턴도 단순함 |

원천 데이터에는 삽입 위치(`insertPositionRatio`)가 있어서 낚시성 0.208, 정상 0.000으로 완벽하게 갈렸습니다. 하지만 정답에서 계산되는 값이라 피처로 쓰지 않았습니다.

## 진단: 모델이 끼워 넣은 문장을 보고 있는가

검증셋의 연예 기사로 테스트셋 두 개를 만들었습니다 (각각 낚시성 1,500 + 정상 1,500).

- A: 연예 기사에 정치 기사 문장 삽입 (누가 봐도 어색함)
- B: 연예 기사에 다른 연예 기사 문장 삽입

재학습한 Part2 베이스라인(F1 0.7634)으로 평가했습니다.

| 테스트셋 | F1 | 낚시성을 잡은 비율 |
|---|---|---|
| A | 0.4626 | 358 / 1,500 (0.24) |
| B | 0.4520 | 335 / 1,500 (0.22) |

누가 봐도 어색한 A에서도 낚시성을 거의 잡지 못했고, B와 차이가 없었습니다. 원래 검증셋의 0.76은 문장의 이질성을 알아본 결과라기보다 학습 데이터의 패턴에 맞춘 결과로 보입니다.

이 결론에는 빈틈이 있습니다.

- 테스트셋은 원 데이터와 삽입 방식이 달라서, 분포가 바뀐 데이터에 일반화하지 못한 것으로도 설명됩니다.
- 정상 기사도 1,139 / 1,500만 맞혔습니다. 연예 기사 자체를 어려워했을 가능성도 있습니다.
- Part1은 모델 파일이 남아 있지 않아 같은 검증을 하지 못했습니다.

다음에 한다면 이질성 강도를 단계별로 바꾼 데이터로 학습하고, 원래 검증셋과 진단셋에서 함께 평가해 보고 싶습니다.

## 시행착오

- **KoBERT가 학습되지 않음**: `skt/kobert-base-v1` 토크나이저가 맞지 않아 loss가 0.69에서 멈추고 F1이 0.33이었습니다. `monologg/kobert`로 바꾸니 0.813이 나왔습니다. 약 7시간을 날렸고, 이후로 loss가 0.69에 멈추면 입력부터 확인합니다.
- **Colab GPU 소진**: Kaggle T4로 옮겼습니다. 긴 학습은 Save & Run All로 돌리고, epoch마다 모델을 저장했습니다.
- **틀린 결론을 발표 직전에 걷어냄**: 테스트셋 A로 새로 학습해 F1 1.00이 나오자 "학습 데이터의 이질성이 부족했다"고 결론을 냈습니다. 하지만 이는 쉬운 문제를 푼 것일 뿐 원래 데이터의 한계를 보여주지 않아서, 최종 발표 전날 해당 슬라이드를 바꿨습니다.
- **라벨 규약 혼동**: 테스트셋 평가 중 낚시성/정상 라벨이 뒤집힌 결과(F1 0.50)가 나와 규약(낚시성=0)을 다시 맞췄습니다.

돌아보면 개선 시도보다 진단 실험을 먼저 돌렸다면 5~6월의 실험 시간을 아낄 수 있었습니다.

## 재현

AI Hub 데이터는 이용약관상 재배포할 수 없습니다. 위 링크에서 신청해 받은 뒤 아래 노트북을 순서대로 돌립니다.

| 단계 | 노트북 |
|---|---|
| 원천 데이터 압축 해제, JSON → CSV | `Part2_Original_Preprocessing`, `TR_preprocessing`, `VL_preprocessing` |
| 학습 파이프라인 | `Pp_Pipeline` |
| 모델 비교 1-1 ~ 2-3 | `capstone-design-1` |
| 피처 추가 1-4 · 2-4 · 2-5 | `scripts/clickbait_ablation_experiment.py` * |
| Part2 베이스라인 재학습 (F1 0.7634) | `train-baseline-p2` |
| 진단 테스트셋 A/B 생성 | `MakeNewDataset` |

삽입 위치 EDA와 문장 쌍 모델(시도 6)은 팀원이 맡은 부분이라 이 저장소에 코드를 넣지 않았습니다.

\* 원본 파일이 남아 있지 않아 작업 기록에서 복원한 스크립트입니다. 실제 실행은 이 코드를 Kaggle 노트북 셀로 나눠서 했고, 셀 버전은 함수 이름과 저장 경로가 조금 다릅니다. 모델(`BertWithFeatures`)과 데이터셋 구조는 같습니다.
